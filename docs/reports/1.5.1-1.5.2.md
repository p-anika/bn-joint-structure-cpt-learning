  (`data/reference/kybernetika-table2.csv`). Expected: 19 STD / 22 MLR / 3 OLR with the same
  type for every node.

## Hand-check for Anika: STD BIC of a3 given a4, from raw counts

**Done by Anika, 2026-11-16: −1142.50831 from the raw counts, matching.**

Target: `bic_std` of a3 in `results/phase1.5/1.5.1-gobnilp-tie-fix/cpt-type-summary.csv` =
**−1142.5083085785432**.

1. Open `data/raw/BN-data.csv` in a spreadsheet (LibreOffice Calc or Excel). Work on a copy or a
   new sheet; never save over the original. 1661 data rows, columns a1…d14.
2. Build the 3 × 3 table of counts of (a4, a3). Put a4 = −1, 0, 1 in cells A2:A4 and
   a3 = −1, 0, 1 in B1:D1. In B2 enter `=COUNTIFS(Data!D:D,$A2,Data!C:C,B$1)`, where `Data` is
   the name of the sheet holding the CSV, column D is a4 and column C is a3 (check the header
   row); fill to D4. A pivot table works too.
   You should get:

   | a4 \ a3 | −1 | 0 | 1 |
   |---|---|---|---|
   | −1 | 1118 | 137 | 114 |
   | 0 | 58 | 61 | 30 |
   | 1 | 68 | 16 | 59 |

   Row totals 1369, 149, 143; grand total 1661.
3. Row totals in E2:E4: `=SUM(B2:D2)`, etc.
4. For each cell compute count × ln(count / row total). In G2: `=B2*LN(B2/$E2)`, fill to I4.
   (No count is 0 here. If one were, its term would be 0.)
5. Log-likelihood: `=SUM(G2:I4)` → **−1120.26278325**.
6. Number of parameters: (k−1)·k^n = 2·3¹ = **6**.
7. Penalty: `=LN(1661)/2*6` → 3.70758755 × 6 = **22.24552533**.
8. BIC = step 5 − step 7 = **−1142.50830858**. It should match the CSV to all digits a
   spreadsheet shows.

Bonus (explainer 04): compute LN(137/1118) = −2.099316. This is exactly MLR's fitted intercept
for child state 0, which shows MLR and STD are the same model here.

## Riskiest assumptions in the code

1. **OLR parent coding:** parents enter as raw −1/0/1 values with one slope each (decision 8).
   The exact Table 2 match supports it, but Jirka hasn't confirmed it.
2. **The 1e-6 tolerance is absolute**, not relative. That is fine for BICs of order 10³ with
   noise of 10⁻¹³. In Phase 2 (thousands of families, possibly zero-count cells where MLR
   doesn't converge exactly) a non-converged MLR could fall just *outside* 1e-6 below STD. It
   would then lose correctly, but the flag must be watched.
3. **statsmodels' convergence flag is trusted as is.** For BFGS (OLR) it means the gradient norm
   fell below statsmodels' default threshold within the default iteration limit. We do not
   independently re-check the gradient.
